# eval-skill

## 1. 目的

スキルの改善によって、既存の問題が解消され、かつ新しい問題が発生していないことを検証する。

評価は、実際のタスクを想定したドライランによって実施する。
評価者の主観や推測ではなく、確認できた事実と出力結果に基づいて判定する。

## 2. 入力

以下を入力として受け取る。

| 入力 | 必須 | 説明 |
|---|---|---|
| 評価対象スキル | 必須 | スキル名または定義ファイルのパス |
| 類似タスク | 必須 | 過去の不具合チケット、実行例など2〜3件 |
| 旧版スキル | 推奨 | 改善前のスキル定義 |
| 改善履歴 | 推奨 | 旧版で発生した問題と修正内容 |

### 入力不足時のルール

- 評価対象スキルが特定できない場合は、評価を開始しない。
- 類似タスクが2件未満の場合は、評価を開始せず、不足している入力を報告する。
- 旧版が存在しない場合は、改善度の比較評価を実施できないため、改善度を `NOT EVALUATED` とする。
- 改善履歴が存在しない場合は、旧版と新版の差分から改善対象を特定する。
- 入力内容が不明確な場合、推測で補完しない。

## 3. 評価の基本ルール

評価中は以下のルールを必ず守る。

1. すべての類似タスクに対して、同一の評価手順を適用する。
2. 旧版と新版の比較では、タスクの入力条件を同一にする。
3. スキル以外の実行条件は、可能な限り統一する。
4. 評価対象スキルに記載されていない手順を、評価者の判断で追加しない。
5. 確認できない項目をPASSにしない。
6. 実行していないテストを、実行済みとして報告しない。
7. 評価中にスキル定義を変更しない。
8. 期待する結果が定義されていない場合は、期待結果を推測せず、その旨を記録する。
9. 各判定には、根拠となる出力、ファイル、行番号、または実行結果を記載する。

## 4. 評価手順

### STEP 1. 評価対象の確認

以下を確認する。

- 評価対象スキルのファイルが存在する。
- スキルの目的と適用範囲が明確である。
- 入力と出力が定義されている。
- 実行手順が記載されている。
- 制約事項や禁止事項が記載されている。
- 旧版と新版を区別できる。

確認結果を記録する。

### STEP 2. 類似タスクの選定

入力された類似タスクから2〜3件を選定する。

選定基準は以下とする。

1. スキルの主目的に直接関係するタスクを優先する。
2. 旧版で不具合が発生したタスクを最低1件含める。
3. 可能であれば、異なる入力条件や境界条件を持つタスクを含める。
4. 同じ内容のタスクを重複して選定しない。

各タスクについて以下を整理する。

- タスクIDまたは名称
- 入力条件
- 期待される動作
- 旧版で発生した問題
- 新版で確認すべき項目

### STEP 3. 旧版のドライラン

旧版が存在する場合、各類似タスクに旧版スキルを適用する。

以下を記録する。

- 実行された手順
- 各手順の出力
- 期待結果との一致・不一致
- 発生した問題
- 問題の発生箇所

旧版のドライラン結果を、新版との比較基準とする。

旧版が存在しない場合は、このSTEPをスキップする。

### STEP 4. 新版のドライラン

各類似タスクに新版スキルを適用する。

すべてのタスクで以下を記録する。

1. スキルの手順に従って実行できたか。
2. 手順の解釈に曖昧さがなかったか。
3. 期待する出力が生成されたか。
4. 出力形式と内容が仕様を満たしているか。
5. 禁止事項や制約事項に違反していないか。
6. 予期しない動作が発生していないか。

タスクごとに結果を保存する。

### STEP 5. 3つの評価軸による評価

以下の3軸を、それぞれ独立して評価する。

#### 5.1 再現性（Reproducibility）

目的：異なる類似タスクに対して、同じスキルが一貫した手順と品質で動作することを確認する。

| ID | チェック項目 | PASS条件 |
|---|---|---|
| R1 | 手順の一貫性 | すべてのタスクで定義された手順が実行される |
| R2 | 入力条件への対応 | 対象範囲内の入力に対して適切に処理できる |
| R3 | 出力形式の一貫性 | すべてのタスクで指定された出力形式を満たす |
| R4 | 判断基準の一貫性 | 同じ条件に対して矛盾する判断をしない |
| R5 | 手順の明確性 | 実行に必要な判断を、未定義の推測に依存しない |

判定ルール：

- すべてのチェック項目がPASSの場合、再現性をPASSとする。
- 1つでもFAILがあれば、再現性をFAILとする。
- 確認できない項目がある場合はNOT EVALUATEDとする。

#### 5.2 改善度（Improvement）

目的：旧版で発生していた問題が新版で解消されていることを確認する。

| ID | チェック項目 | PASS条件 |
|---|---|---|
| I1 | 既知不具合の解消 | 旧版で発生した問題が新版で再発しない |
| I2 | 修正内容の反映 | 改善履歴に記載された修正がスキルに反映されている |
| I3 | 期待動作の実現 | 改善対象のタスクで期待結果が得られる |
| I4 | 回帰の防止 | 旧版で正常だった動作が新版でも維持される |

判定ルール：

- すべてのチェック項目がPASSの場合、改善度をPASSとする。
- 1つでもFAILがあれば、改善度をFAILとする。
- 旧版が存在しない場合はNOT EVALUATEDとする。
- 比較対象となる不具合や期待動作が特定できない場合もNOT EVALUATEDとする。

#### 5.3 副作用（Side Effects）

目的：改善によって新しい問題や予期しない動作が発生していないことを確認する。

| ID | チェック項目 | PASS条件 |
|---|---|---|
| S1 | 既存機能への影響 | 改善対象外の既存動作が維持されている |
| S2 | 過剰な処理 | 不必要な処理や手順が追加されていない |
| S3 | 入力範囲への影響 | 従来対応できていた入力が拒否されていない |
| S4 | 出力への影響 | 意図しない出力の欠落や変更がない |
| S5 | 安全性 | 権限逸脱、データ破壊、機密情報の漏洩などの問題がない |
| S6 | 制約事項 | スキルの適用範囲や禁止事項が守られている |

判定ルール：

- すべてのチェック項目がPASSの場合、副作用をPASSとする。
- 1つでもFAILがあれば、副作用をFAILとする。
- 検証できない項目がある場合はNOT EVALUATEDとする。

## 5. 評価結果の判定

各評価軸は以下の3種類で判定する。

| 判定 | 意味 |
|---|---|
| PASS | すべてのチェック項目が合格 |
| FAIL | 1つ以上のチェック項目で不合格 |
| NOT EVALUATED | 必要な情報や検証結果が不足している |

### 総合評価

以下のルールを厳守する。

| 再現性 | 改善度 | 副作用 | 総合評価 |
|---|---|---|---|
| PASS | PASS | PASS | PASS |
| FAIL | 任意 | 任意 | FAIL |
| 任意 | FAIL | 任意 | FAIL |
| 任意 | 任意 | FAIL | FAIL |
| NOT EVALUATED | 任意 | 任意 | NOT EVALUATED |
| 任意 | NOT EVALUATED | 任意 | NOT EVALUATED |
| 任意 | 任意 | NOT EVALUATED | NOT EVALUATED |

FAILが1つでも存在する場合は、NOT EVALUATEDよりFAILを優先する。

NOT EVALUATEDが1つでも存在し、FAILがない場合は、総合評価をNOT EVALUATEDとする。

### 判定上の禁止事項

- 一部のPASSを理由に、全体をPASSにしない。
- 重大な問題を、軽微な問題として扱わない。
- 根拠がない場合にPASSと判定しない。
- テスト未実施をPASSとして扱わない。
- 評価者の期待や好みを判定基準にしない。

## 6. 評価レポートの作成

評価結果を以下のパスにMarkdown形式で出力する。

`docs/dryrun-reports/eval_report_YYYYMMDD_HHMMSS.md`

ファイル名の日時は、レポート作成時のローカル時刻を使用する。

出力ディレクトリが存在しない場合は作成する。

## 7. 評価結果のフィードバック

評価レポートの作成後、改善案の作成プロセスに以下を返す。

1. 総合評価
2. 各評価軸の判定
3. 発見された問題
4. 問題の根拠
5. 改善提案
6. 次回評価で確認すべき項目

### 総合評価がPASSの場合

- 評価結果を改善プロセスに返す。
- 検証済みの変更を維持する。
- 新たな変更は要求しない。

### 総合評価がFAILの場合

- FAILとなった項目を明示する。
- 問題の発生条件と根拠を返す。
- 改善案の再検討を要求する。
- 修正後は同じテストケースで再評価する。

### 総合評価がNOT EVALUATEDの場合

- 評価できなかった項目を明示する。
- 不足している入力や検証条件を返す。
- 不足情報が補完されるまでPASSと判定しない。

## 8. 最終ルール

- 評価は必ず本スキルに定義された基準に従う。
- 評価基準を実行途中で変更しない。
- すべての判定に根拠を記載する。
- 未実施のテストを実施済みと報告しない。
- 評価結果と改善提案を混同しない。
- 総合評価がPASSになるまで、改善完了と判断しない。
